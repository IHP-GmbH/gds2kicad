# I/O Pads Library

Parametric KiCad symbol/footprint generator for external I/O pads on the
interposer. Lets you instantiate one symbol per external pin in your
schematic, place its footprint in your PCB, and have downstream tooling
render the corresponding TopMetal2 geometry in the interposer GDS.

## Currently supported

- `wire_bond` -- square TopMetal2 pad for external wire bonding (default 100x100 um, configurable).

## Future I/O classes (architecture supports drop-in)

- `flipped_bump` -- bottom-side bump for flipped-interposer-to-PCB packaging.
- `tsv_bump` -- backside bump connected through TSVs.

These classes are reserved in the CLI but rejected at generation time
until the corresponding renderer lands in `hyp_to_gds.py`.

## Generate a library entry

```bash
python generate_io_pad.py --io-class wire_bond --size 100x100
# writes:
#   io_pads/kicad_symbols/IOPad_WireBond_100x100.kicad_sym
#   io_pads/kicad_footprints/IOPad_WireBond_100x100.kicad_mod
```

The generated footprint carries two KiCad properties used downstream:

| Property         | Purpose                                                          |
| ---------------- | ---------------------------------------------------------------- |
| `IO_CLASS`       | Selects the dispatcher branch in `hyp_to_gds.py`.                |
| `IO_PAD_SIZE_UM` | Geometric parameter, `<W>x<H>` in micrometers (e.g. `100x100`).  |

Pre-generated entries committed to the repo:

- `kicad_symbols/IOPad_WireBond_100x100.kicad_sym`
- `kicad_footprints/IOPad_WireBond_100x100.kicad_mod`

Other sizes can be produced on demand with the same script.

## Add the library to your KiCad project

1. KiCad -> Preferences -> Manage Symbol Libraries -> Project tab, add an
   entry pointing to `io_pads/kicad_symbols/IOPad_WireBond_100x100.kicad_sym`
   (KiCad treats each `.kicad_sym` as a single-symbol library; for multiple
   sizes, add them all under a `io_pads` nickname or use a single library
   file generated by concatenation).
2. Manage Footprint Libraries -> Project tab, add an entry pointing to
   `io_pads/kicad_footprints/` (KiCad treats a folder of `.kicad_mod`
   files as a footprint library; use the nickname `io_pads`).
3. In your schematic, place `IOPad_WireBond_100x100` symbols and wire each
   one to the external net you want to expose. In your PCB, place the
   matching footprints at the desired positions on the interposer top
   edge. The `IO_CLASS` and `IO_PAD_SIZE_UM` properties travel with the
   footprint.

## Extract pad locations from a routed PCB

```bash
python kicad_pcb_to_iopads.py path/to/design.kicad_pcb -o io_pads.json
```

Walks all footprints in the PCB, filters those whose property `IO_CLASS`
is set, and emits a sidecar JSON consumed by `hyp_to_gds.py --io-pads`.

Coordinate convention: KiCad PCB stores positions Y-down in millimeters.
The output JSON is in micrometers with Y negated to match the GDS Y-up
convention used by `hyp_to_gds.py`.

## End-to-end workflow

```
1) generate_io_pad.py     -> kicad_symbols/, kicad_footprints/
2) Design schematic + PCB in KiCad (place footprints, route)
3) kicad_pcb_to_iopads.py -> io_pads.json
4) hyp_to_gds.py --io-pads io_pads.json
                          -> interposer.gds (TopMetal2 squares at the pad locations)
                          -> updated .chiplet (io_pads block under the
                             interposer component, external nets marked)
```
